# 機能要件(詳細)

## FR-1 音声取り込み

- PWAがマイクから音声を取得し、圧縮したうえでWebSocketでサーバーへ連続送信する。
- 通信断が発生した場合、再接続後に同一セッションへ復帰できること。
- 送信を一時停止/再開できること(機密情報を話す場面での中断用)。

## FR-2 リアルタイム文字起こし

- サーバーは受信した音声を音声認識APIへ中継し、確定前テキスト(partial)と確定テキスト(final)を受け取る。
- 確定テキストは即座にPWAへ返し、画面に反映する。
- 話者分離が利用できる場合は話者ラベルを保持する。利用できない場合も処理は継続する。

## FR-3 Markdown正規化

- 確定テキストは即座に `transcript.md` に追記される。
- 音声以外の入力(Circleback / Notion / 手入力)も、同じMarkdown形式へ正規化してから後続処理に渡す。
- 以降のすべてのAI処理は、音声かどうかを一切意識しない。

## FR-4 逐次分析

- 一定間隔(既定60秒)および文字起こしの一定量蓄積ごとに、課題抽出・アイデア抽出を実行する。
- 分析結果は `issues.md` / `ideas.md` に追記し、リアルタイムでPWAに反映する。
- 商談中に画面共有できる粒度で表示すること(これ自体がデモ価値になる)。

## FR-5 生成トリガー

- 開始キーワード(「この内容でアプリ作って」等)を文字起こしから検出したらMVP生成を開始する。
- 手動の「MVP生成」ボタンからも同じ処理を開始できる。
- **誤検知を避けるため、検出時はPWAに確認UIを出し、営業担当が明示的に承認するまで生成を開始しない。** 自動承認はしない。
- 承認されないまま次のトリガーが検出された場合は、前の確認UIを差し替える。

## FR-6 MVP生成

- `requirements.md` を入力として、動作するWebアプリのソースコードを生成する。
- **生成は承認された時点で開始し、商談中に並行して実行する。** 商談終了を待たない。
- 生成物は**静的にビルドできるSPA**であること(Gateway Serverが自前配信するため、サーバーサイド実行を必要としない)。
- ビルドが通ること。失敗時は最大N回(既定3回)まで自動修正を試行する。
- 生成対象のスコープは「1画面〜3画面程度の業務改善アプリ」に限定する。
- 承認から配信開始までを10分以内に収める。

## FR-7 デプロイとURL提示

- 生成されたアプリは**Gateway Server自身が配信する。外部ホスティングへはデプロイしない。**
- URLはセッショントークンを含み、トークンを持たないアクセスは拒否する。ネット上に公開しない。
- URLはQRコードでも表示する。営業担当が自分の別端末(PC → タブレット等)で開くための手段とする。
- 生成物はセッションの有効期間中のみ配信し、セッション失効と同時に配信を停止する。

## FR-8 セッション終了

- 終了ボタン / 終了キーワード / 一定時間無音(既定10分)のいずれかでセッションを終了する。
- 終了時に `summary.md` を生成し、成果物一式(Markdown + アプリURL)をまとめて提示する。

## 非機能要件(数値まとめ)

| 項目 | 目標値 | 備考 |
| --- | --- | --- |
| 文字起こし遅延 | 発話終了から3秒以内に画面反映 | 商談の流れを止めないこと |
| Markdown更新 | 5秒以内 | `transcript.md` / `issues.md` 等への反映 |
| MVP生成の開始 | 承認から30秒以内 | 確認UIの承認操作以降を計測する |
| MVP生成の完了 | 承認から10分以内 | コード生成・レビュー差し戻し・配信開始までを含む |
| 商談終了後のURL生成 | 30秒以内 | 商談中に生成済みのため、終了イベントからURL提示まで |
| 同時セッション数 | 初期は1〜3 | 営業担当が使う想定。水平分割で拡張 |
| サーバーリソース | CPU最小構成 / メモリ2GB | 重い処理はすべて外部APIへ委譲 |
| 通信帯域 | モバイル回線で動作 | 圧縮音声を使用 |
| 可用性 | 自動再接続で継続 | 切断中のMarkdownは保持し、再接続後に続きから処理 |

## ログ要件(詳細)

- 全イベント(WebSocketの送受信、状態遷移)を時系列でセッション単位に保存する。
- Agent実行履歴として、Agent名・入力Markdown・出力Markdown・所要時間・使用モデルを保存する。
- エラー履歴として、発生時刻・発生箇所・エラーコード・リトライ回数・最終的な縮退動作を保存する。
- ログには音声データそのものを含めない。文字起こし結果のテキストのみを保持する。

# セキュリティ・プライバシー要件

- 商談の音声は、相手方の同意を得たうえで取得する。PWAは録音中であることを常時明示する。
- 音声データはサーバーに永続保存しない。文字起こし結果(テキスト)のみを保存する。
- 生成されたMarkdownおよびアプリは、セッション単位でアクセス制御する。
- APIキー・デプロイトークンはサーバー側の環境変数のみで管理し、リポジトリにも生成物にも含めない。
- 生成されたデモアプリはGateway Serverが配信し、セッショントークンを持つアクセスのみ許可する。ネット上に公開しない。
- それでも生成アプリは商談内容から作られるため、実データ(顧客名・実在の数値等)は投入しないことを運用ルールとする。
